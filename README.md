# iPhone Mirror — Windows 미러링 프로토타입

아이폰 화면을 Windows 11에서 보는 첫 단계입니다. 한국어 WPF 안내창이 UxPlay 수신기를 실행하고, 아이폰 영상은 수신기의 별도 창에 표시됩니다.

## 실행

1. 이 폴더의 `iPhoneMirror.exe`를 실행합니다. `runtime` 폴더도 같은 위치에 있어야 합니다.
2. PC와 아이폰을 같은 공유기에 연결합니다. PC의 유선 LAN도 가능합니다.
3. 앱에서 **미러링 시작**을 누르고 방화벽 보조 프로세스(Windows PowerShell)의 관리자 승인을 확인합니다. 승인을 취소하면 수신기를 시작하지 않습니다.
4. 아이폰 잠금을 해제한 뒤 **제어 센터 → 화면 미러링 → iPhone Mirror**를 선택합니다.
5. 암호를 요청하면 Windows 안내창의 6자리 연결 코드를 입력합니다.
6. **미러링 중지**를 누르거나 안내창을 닫으면 수신기를 종료한 뒤 이 실행의 임시 방화벽 규칙을 삭제하고 확인합니다. 정리 실패는 화면과 로그에 알립니다.

연결 코드는 시작할 때마다 새로 만들어집니다. 아이폰 소리 재생은 옵션입니다. 검은 화면/멈춤이 있으면 중지하고 **호환 모드**를 켠 뒤 다시 연결합니다. 영상 창은 Alt+Enter로 전체 화면을 전환할 수 있습니다.

아이폰 영상이 가로·세로로 바뀌면 일반 영상 창도 수신 비율에 맞춰 자동으로 크기를 바꿉니다. 현재 긴 변의 길이를 기준으로 조정하고 모니터 작업 영역 안에 맞춥니다. 같은 비율에서는 사용자가 조정한 창 크기를 유지합니다. 최대화·최소화·전체 화면에서는 그 상태를 유지하며, 일반 창으로 돌아왔을 때 최신 영상 비율을 적용합니다.

## 지금 가능한 범위와 검증 범위

- 구현: 수신기 실행·중지, 연결 코드 표시, 한국어 안내, 진단 로그, 소리 재생 옵션, 소프트웨어 디코딩 옵션, 수신 영상 비율에 따른 창 자동 크기 조정. 방화벽 자동 관리는 정상 시작·중지에 대한 사용자 확인을 마쳤으며, 강제 종료·재부팅에 관한 검증 제한은 아래를 참고하세요.
- PC 검증 결과는 `artifacts/smoke-test.txt`에 기록됩니다. 로컬 RTSP 응답 성공은 아이폰 화면 수신 성공을 뜻하지 않습니다.
- 대상 기기: 사용자가 알려 준 iPhone 17 Pro Max / iOS 27. 2026-10-12 사용자는 기본 미러링과 영상 회전이 정상이며, 수정 후 영상 창도 가로·세로로 자동 조정된다고 확인했습니다. **1단계 실기기 사용자 확인 완료**입니다.
- 마우스 터치, 홈 이동, 키보드, 클립보드, 파일 전송은 아직 구현하지 않았습니다.
- 아이폰이 잠겨 있는 상태에서 사용하는 Apple의 Mac 전용 iPhone 미러링과는 동작 범위가 다릅니다.
- 보호된 영상 콘텐츠는 수신 엔진의 제한 때문에 표시되지 않을 수 있습니다.

## 연결이 안 될 때

1. `Bonjour Service`가 실행 중인지 확인합니다. Bonjour가 없다면 먼저 설치해야 합니다. 이 프로젝트는 서비스를 설치하거나 자동 시작 설정을 바꾸지 않습니다.
2. Windows의 현재 네트워크 프로필과 방화벽을 확인합니다. 신뢰하는 가정용 네트워크에서 사용할 경우 프로필을 `개인`으로 설정합니다.
3. 앱은 **이 수신기 실행 파일만**, **개인 네트워크의 같은 서브넷만**, **TCP/UDP 7100–7102만** 임시 허용하도록 구성되어 있습니다. 공용 네트워크 프로필은 변경하지 않습니다. Bonjour 검색은 기존 서비스의 UDP 5353 통신 규칙을 사용합니다.
4. `./configure-firewall.ps1`은 현재 앱 규칙을 조회합니다. 영구 허용 규칙을 새로 만들지 않습니다. 기존 프로토타입 규칙 두 개만 수동 제거하려면 관리자 PowerShell에서 `./configure-firewall.ps1 -Remove`를 실행합니다. 실행 파일 경로가 다르면 제거하지 않습니다.
5. 공유기의 기기 격리, 게스트 Wi-Fi, VPN은 검색을 방해할 수 있습니다.
6. 진단 로그는 `logs/receiver.log`와 `logs/firewall.log`입니다. 수신기 로그에는 기기 이름·주소가 포함될 수 있으므로 외부 공유 전 확인하세요. 화면이나 소리는 파일로 녹화하지 않습니다.

## 빌드와 재현

Windows x64에 포함된 .NET Framework C# 컴파일러를 사용합니다. 별도 .NET SDK나 NuGet 패키지가 필요하지 않습니다.

```powershell
./setup-runtime.ps1  # 최초 1회, 고정 버전 다운로드와 SHA-256 검증, 파일 추출
./build.ps1
./iPhoneMirror.exe
```

검증 명령:

```powershell
$p = Start-Process ./iPhoneMirror.exe -ArgumentList '--smoke' -WindowStyle Hidden -PassThru -Wait
$p.ExitCode
Get-Content ./artifacts/smoke-test.txt
```

`--smoke`는 방화벽을 변경하지 않고 수신기 기동, 로컬 RTSP OPTIONS 응답, 프로세스 종료를 두 번 검증합니다. 두 번째는 소프트웨어 디코딩 설정으로 시작합니다. 실제 비디오 디코딩은 아이폰 연결 후 확인해야 합니다. `--render`는 안내창의 WPF 렌더링 이미지를 `artifacts/preview.png`에 만듭니다. `--start`는 안내창을 열면서 관리자 승인과 수신 시작 절차도 진행합니다.

`./tests/test-rotation.ps1`은 포함된 GStreamer 런타임으로 시험 영상을 생성해 실제 D3D11 창에서 세로→가로→세로 변경, 수동 크기 유지, 최대화·최소화·전체 화면 복귀, 모니터 경계 처리를 검증합니다. 시험 중 영상 창이 잠시 나타납니다. 결과는 `artifacts/rotation-test.txt`에 기록됩니다.

`./verify.ps1`의 기본 동작은 빌드·안내창 렌더·방화벽 모의 시험입니다. 방화벽 모의 시험은 NetSecurity 명령을 메모리 모형으로 대체하며 시스템 규칙을 변경하지 않습니다. 결과는 `artifacts/firewall-rules-test.txt`입니다. 기존 수신기·영상 시험을 함께 실행하려면 `./verify.ps1 -LiveReceiver`를 사용합니다. 이 옵션도 실제 방화벽 변경이나 재부팅 시험을 수행하지 않습니다.

자동 크기 조정은 고정된 런타임의 `d3d11videosink` 협상 완료 caps 진단에서 실제 너비·높이·픽셀 비율을 읽습니다. 해당 범주의 진단만 활성화하며 프레임·패킷 추적은 켜지 않습니다. 런타임을 교체할 때는 진단 형식이 유지되는지 회전 통합 시험과 실기기로 다시 확인해야 합니다.

### 방화벽 자동 관리 — 구현과 검증 범위

- 일반 권한의 WPF 앱이 시작할 때 관리자 권한의 `scripts/FirewallGuard.ps1`을 별도로 실행한다. 로컬 명명된 파이프로 준비·중지·정리 결과를 주고받고, UI는 승인·정리 중에도 응답하도록 비동기로 처리한다.
- 보조 프로세스는 표준 NetSecurity 명령으로 `ActiveStore`에 임시 규칙을 만들고 적용 범위를 다시 조회한다. 두 규칙이 모두 확인된 후에만 수신기를 시작한다. 관리자 승인 취소·정책 제한·생성 실패 시 수신기를 시작하지 않는다.
- 정상 중지·종료 시 수신기를 먼저 종료하고 규칙을 제거한다. 보조 프로세스는 메인 앱 및 수신기의 종료를 감시한다. 수신기는 종료 시 자식 프로세스를 정리하는 Windows Job에도 연결한다.
- 보조 프로세스까지 동시에 강제 종료되거나 정리 명령이 실패한 경우, 규칙이 즉시 사라짐을 보장하지 않는다. 수신을 중단하고 오류를 알리며 다음 시작에서 같은 설치 경로의 남은 관리 규칙을 회수한다. 영구 저장소에 새 규칙을 쓰지 않는 설계이며, 재부팅 시 동작은 실제 시험하지 않았다.
- 기존 범위(지정 실행 파일, 개인 네트워크, 같은 서브넷, TCP/UDP 7100–7102)를 유지한다. 기존 프로토타입 규칙 두 개는 첫 정상 적용 시 정확한 이름과 실행 파일 경로를 확인한 뒤 제거한다. 다른 앱·다른 설치 경로·Bonjour 규칙은 변경하지 않는다.
- 모의 시험: 시작/중지, 기존 규칙 전환, 다른 설치 경로 보호, 부분 생성 실패 되돌리기, 과도한 허용 범위 거부, 네트워크·정책 제한, 조회 권한 오류, 정리 실패, 남은 규칙 복구를 검증한다. 자동 시험은 실제 UAC·방화벽 쓰기·강제 종료·재부팅을 실행하지 않는다.

2026-10-12 별도 네이티브 방화벽 API 시험 직후 `0xEF` 시스템 재부팅이 관측됐다. 인과관계는 미확정이며 해당 시험 코드는 이 저장소와 앱에 포함하지 않는다. 같은 네이티브 시험과 PC 강제 종료·재부팅 재현 시험은 실행하지 않는다. 이후 표준 NetSecurity 방식으로 대체하고 빌드·렌더·12개 모의 시험을 통과했다. 사용자가 직접 시작·관리자 승인·중지 절차를 수행한 뒤 정상 동작을 확인했다. 2026-10-12 실행 기록에서 임시 규칙 적용과 삭제 후 부재 확인이 모두 성공했고, 종료 후 앱 규칙과 수신기 프로세스가 남지 않았음을 확인했다. 기존 프로토타입 영구 규칙 두 개도 전환 과정에서 제거됐다. 이 확인은 정상 실행·중지에 한정하며 강제 종료·재부팅 동작은 시험하지 않았다.

### 화질 개선 계획 — 검토 전

- 현재 화면을 기준으로 작은 글자, 사진, 스크롤, 가로·세로 회전, 창 확대 시의 선명도와 끊김을 비교한다.
- 아이폰이 실제로 전송하는 해상도·프레임률과 PC 표시 배율을 확인한다. 요청 해상도·프레임률이 실제 수신값을 보장한다고 가정하지 않는다.
- 수신 엔진에서 조정 가능한 해상도, 디코더, 렌더링·스케일링 설정을 조사하고 적용 전후를 비교한다. 비트레이트·코덱 설정은 아이폰과 엔진에서 실제 지원·제어 가능한지 먼저 확인한다.
- 화질과 지연·안정성의 균형을 검증한다. 필요하면 선명도 우선·반응속도 우선 설정을 검토하며, 지원이 확인되지 않은 고해상도나 프레임률을 보장하지 않는다.
- 사용자에게 같은 화면으로 개선 전후를 직접 확인해 달라고 요청하고, 확인 결과를 기록한 뒤 해당 단계의 커밋·푸시를 진행한다.

## 단계 완료 및 커밋·푸시 절차

1. 한 단계의 구현과 PC에서 가능한 검증을 마친다.
2. 사용자에게 완료한 기능, 검증 결과, 아이폰에서 확인할 동작을 구체적으로 안내하고 **동작 확인을 요청**한다.
3. 사용자 확인 전에는 해당 단계를 완료 처리하거나 커밋·푸시하지 않는다. 문제가 있으면 수정 후 다시 확인을 요청한다.
4. 사용자가 정상 동작을 확인하면 해당 단계의 변경을 커밋하고 푸시한 뒤 커밋과 결과를 안내한다.

**최초 스냅샷 예외:** 2026-10-12 사용자가 지금까지의 작업은 즉시 최초 커밋·푸시하도록 별도로 요청했다. 따라서 현재 소스와 계획은 초기 상태로 저장하지만, 아이폰에서 1단계가 정상 동작한다는 확인을 받은 것으로 간주하지 않는다. 저장소 공개 범위는 이후 정정한 요청에 따라 **public**으로 한다.
